Timelines are reconstructed from each platform's own revision history — ECS task definition revisions (stamped with their registration time) and EKS ReplicaSet history — using that timestamp as a proxy for "went live". That holds in typical CI/CD flows where register-and-deploy happen together, but isn't a guaranteed audit record of the actual deploy action. A service deleted before this report was generated won't appear, even if it was live during part of this window. A ? next to a commit means it couldn't be verified against the GitHub API.

Where configured, Harness executions and New Relic deployment markers are shown alongside each service's timeline as independent corroborating evidence, not merged into it — use them to sanity-check the reconstructed dates rather than as the primary record.
