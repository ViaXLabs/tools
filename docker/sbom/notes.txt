Answers, in order:

**Syft or Grype, or both?** Both — they're not alternatives. Syft catalogs what's installed (your original ask). Grype reads that catalog and cross-references it against CVE databases. Grype doesn't scan images itself in this design — it rescans the SBOM Syft already produced (`grype sbom:path/to.cdx.json`), so it's fast and needs no registry access at all, only the archived SBOM file.

**Does Syft have a built-in report format?** No HTML, no. Default output with no `-o` flag is a plain-text table. It supports Go templates (`-o template -t file.tmpl`) for custom formats, but a template only sees *that tool's own* data — a Syft template can't also show CVE counts, and a Grype template can't show every installed package (only the ones with a match). Since you want one row per image with both, that has to be assembled outside either tool — which is what `render_fleet_report.py` does.

Updated pipeline (four scripts now, each independently re-runnable):

1. `nexus_list_images.py` → `nexus-images.txt`
2. `fleet_sbom_scan.py` → SBOMs + `fleet-versions.csv`
3. `fleet_vuln_scan.py fleet-versions.csv` → rescans each SBOM with Grype, writes `fleet-vulns-summary.csv` + full CVE reports in `vulns/`. Optional `FAIL_ON=high` env var fails the whole script (exit 1) if any image has a high/critical CVE — a ready-made CI gate if you want one.
4. `render_fleet_report.py fleet-versions.csv fleet-vulns-summary.csv fleet-report.html` → one self-contained HTML file, no external CSS/JS/fonts, so your Confluence-publish step can take it as-is. Per-image CVE lists are behind a native `<details>` toggle rather than always expanded, so a 200-image fleet doesn't become an unreadable wall on the page.
