Quick gut check before the file: this exact symptom — "should be 13, keeps coming out as something else" — usually traces to one of two things, and I want to flag them since they'll matter more than the Dockerfile itself.

**1. Alpine + Cypress don't officially get along.** Cypress's own docs are explicit that Cypress on Linux requires a minimum glibc version of 2.17, and since glibc ships with the OS, that can't be changed — and Alpine doesn't ship glibc at all, it uses musl. Cypress's supported Linux list is Ubuntu/Fedora/Debian, never Alpine. It can be coaxed to run on Alpine with a compat shim (`gcompat`), but that's a workaround, not something Cypress guarantees will keep working release over release. If your `alpine_node22_cypress` family already works for v15 and v17, you're probably already relying on that shim and it's fine — just know it's the reason things get flaky sometimes.

**2. This is very likely why you're getting the wrong version.** I checked npm just now — the latest published Cypress version is 15.19.0. If anywhere in the Dockerfile or a Harness build-arg the version isn't explicitly pinned (e.g. a bare `npm install -g cypress` instead of `cypress@13.x.x`), npm silently grabs whatever `latest` is — right now that's 15.x. That would explain "I ask for 13, I get 15" perfectly, with zero need for anything exotic. Also worth checking: does your Harness step actually pass `--build-arg CYPRESS_VERSION=...`, or is there a hardcoded default in the Dockerfile it's falling back to? And is Harness doing Docker layer caching that might be replaying an old `RUN npm install -g cypress` layer from a previous v15 build?

Here's a Dockerfile that pins the version explicitly, wipes out anything a base layer might have baked in, and — critically — fails the build loudly if the installed version doesn't match what you asked for, instead of silently shipping the wrong one.A few things to actually check once you've transferred this over:

- **Build and tag it to match your convention:**
  ```
  docker build --build-arg CYPRESS_VERSION=13.21.0 -t alpine_node22_cypress:13 .
  docker run --rm alpine_node22_cypress:13 --version
  ```
  Confirm the printed version matches before pushing anywhere.

- **Compare against your existing Dockerfile specifically for:** whether `cypress` is installed with `@<version>` at all, or just bare `npm install cypress`/`-g cypress`. That's the #1 suspect for "asked for 13, got something else."

- **In Harness**, check whether the pipeline variable meant to control the version is actually wired into a `--build-arg` on the docker build step — a disconnected variable would silently build with whatever default the Dockerfile falls back to. Also worth a one-off `--no-cache` build to rule out a stale cached layer from a prior v15/v17 build being reused.

# syntax=docker/dockerfile:1
#
# Build:  docker build --build-arg CYPRESS_VERSION=13.21.0 -t alpine_node22_cypress:13 .
# Verify: docker run --rm alpine_node22_cypress:13 --version
#
# NOTE ON ALPINE: Cypress's binary is built against glibc, and Alpine uses
# musl instead. Cypress officially supports Ubuntu/Debian/Fedora only.
# This Dockerfile uses gcompat as a best-effort glibc shim so Cypress can
# run at all on Alpine. If a future Cypress release leans on a glibc
# feature gcompat doesn't cover, this can break even with the version
# pinned correctly below -- that's an Alpine limitation, not a typo here.
# If you hit that wall, the officially supported path is a Debian-based
# image (cypress/base, cypress/browsers, or the cypress/factory image,
# which lets you generate a custom Node+Cypress+browser combo without
# fighting musl at all).

FROM node:22-alpine

# ---- Pin the exact Cypress version here ----
# A tag like ":13" really means one specific patch in the 13.x line.
# 13.21.0 is the last 13.x release before Cypress 14 -- swap this for
# whichever 13.x patch your team has actually standardized on.
ARG CYPRESS_VERSION=13.21.0

# Packages Cypress needs to actually launch and drive a browser headless,
# plus gcompat/libc6-compat as the glibc shim mentioned above.
RUN apk add --no-cache \
        chromium \
        nss \
        freetype \
        freetype-dev \
        harfbuzz \
        ca-certificates \
        ttf-freefont \
        udev \
        xvfb \
        gcompat \
        libc6-compat \
        bash \
        git \
        python3 \
        make \
        g++

ENV CYPRESS_CACHE_FOLDER=/root/.cache/Cypress

WORKDIR /app

# Wipe any Cypress a parent/base layer might already have installed, so a
# stale version (e.g. 15.x pulled into an earlier layer of this same base)
# can't shadow the one we're about to install.
RUN npm uninstall -g cypress 2>/dev/null || true \
    && rm -rf /root/.cache/Cypress \
    && rm -rf /usr/local/lib/node_modules/cypress

# Install the EXACT pinned version. Never a bare `npm install -g cypress`
# -- that resolves to whatever npm's "latest" dist-tag is at build time
# (currently 15.x), which is the most likely reason you're not landing on 13.
RUN npm install -g cypress@${CYPRESS_VERSION}

# Fail the build here -- not three stages downstream in someone else's
# pipeline -- if the resolved version drifted from what was requested,
# or if the binary can't actually execute under musl/gcompat.
RUN installed="$(cypress --version | head -n1)"; \
    echo "$installed"; \
    echo "$installed" | grep -q "${CYPRESS_VERSION}" || \
      (echo "ERROR: expected Cypress ${CYPRESS_VERSION}, got: $installed" && exit 1)
RUN cypress verify

ENTRYPOINT ["cypress"]
