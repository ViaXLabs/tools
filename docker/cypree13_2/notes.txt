Quick gut check before the file: this exact symptom — "should be 13, keeps coming out as something else" — usually traces to one of two things, and I want to flag them since they'll matter more than the Dockerfile itself.

**1. Alpine + Cypress don't officially get along.** Cypress's own docs are explicit that Cypress on Linux requires a minimum glibc version of 2.17, and since glibc ships with the OS, that can't be changed — and Alpine doesn't ship glibc at all, it uses musl. Cypress's supported Linux list is Ubuntu/Fedora/Debian, never Alpine. It can be coaxed to run on Alpine with a compat shim (`gcompat`), but that's a workaround, not something Cypress guarantees will keep working release over release. If your `alpine_node22_cypress` family already works for v15 and v17, you're probably already relying on that shim and it's fine — just know it's the reason things get flaky sometimes.

**2. This is very likely why you're getting the wrong version.** I checked npm just now — the latest published Cypress version is 15.19.0. If anywhere in the Dockerfile or a Harness build-arg the version isn't explicitly pinned (e.g. a bare `npm install -g cypress` instead of `cypress@13.x.x`), npm silently grabs whatever `latest` is — right now that's 15.x. That would explain "I ask for 13, I get 15" perfectly, with zero need for anything exotic. Also worth checking: does your Harness step actually pass `--build-arg CYPRESS_VERSION=...`, or is there a hardcoded default in the Dockerfile it's falling back to? And is Harness doing Docker layer caching that might be replaying an old `RUN npm install -g cypress` layer from a previous v15 build?
