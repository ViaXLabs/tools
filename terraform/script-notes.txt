Here's what it does:

Checks first, deletes second — shows you the lock's age and contents (who/what/when, straight from the .tflock JSON) before touching anything.
Age safety net — won't auto-delete a lock younger than 15 minutes (configurable) unless you explicitly override it, so you don't accidentally kill an in-progress run.
Confirmation prompt by default — add --force to skip it for scripted/automated use later.
Clear exit codes (0/1/2/3/4) so you can eventually wire this into monitoring or a pipeline step without guessing what happened.

Usage:

bash
chmod +x tf-unlock-s3.sh
./tf-unlock-s3.sh my-tf-bucket prod/infrastructure/terraform.tfstate

Or skip the age check and prompt entirely if you already know it's stale:

bash
./tf-unlock-s3.sh my-tf-bucket prod/infrastructure/terraform.tfstate 0 --force

Requires the AWS CLI configured with creds that can s3:GetObject/s3:DeleteObject on that bucket — same permissions you're presumably already using in Harness.
